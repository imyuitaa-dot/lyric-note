# Lyric Note (Phase 9まで実装済み)

洋楽和訳・歌詞解釈ノート個人用Webアプリ。HTML / CSS / Vanilla JavaScript / IndexedDBのみで構築。

## Phase 0 でできること

- HOME画面(検索・曲を追加・曲一覧・アーティスト別・グループ別・お気に入り・設定の入り口)
- ハッシュルーティング(`#/settings` など)による画面切り替え
- IndexedDBの初期化(songs / artists / groups / groupSongs / images / drafts / settings の7ストア)
- 設定画面でのDB接続確認、ホーム画面追加状態の確認、永続化リクエスト
- 上記以外の画面は「準備中」表示(Phase 1以降で実装)

## Phase 1 でできること

- 曲の追加(曲名・アーティスト・アルバム、歌詞ブロックの手動追加/削除)
- 曲一覧(曲名/追加順 × 昇順/降順の並び替え)
- 曲詳細(和訳ON/OFF、お気に入りハート、歌詞ブロック表示、編集ボタン)
- 曲全体メモ(自由記述、フォーカスを外すと自動保存)
- お気に入り一覧
- アーティスト名の表記ゆれ正規化(大文字小文字・前後の空白を無視して同一アーティストとして扱う)

## Phase 2 でできること

- 歌詞のまとめ貼り付け→自動でブロック生成
  - `[Verse 1]` `[Chorus]` のような見出し行があれば、見出しごとにブロックを分割
  - 見出しが無ければ、空行で区切られたまとまりを1ブロックとして扱う
  - 英語と日本語でまとまりの数が違う場合は「ズレ」を通知(データは壊さない)
- ブロックの↑↓による手動並び替え
- 下書きの自動保存(入力後、少し経つと自動保存。曲の追加/編集画面を開くと、
  保存されていない下書きがあれば復元バナーが出る)

## Phase 3 でできること

- 英語または日本語の歌詞の一部を選択すると、画面下部に「メモを追加」バーが出る
- メモを保存すると、対象部分に点線の下線が表示される(通常はメモ本文非表示)
- 下線をタップすると、ポップアップでメモの内容を表示・編集・削除できる
- 同じブロック・同じ言語内でのメモの重なりは禁止(重ねて選択すると既存メモが開く)
- 歌詞を編集して文字位置がずれた場合、自動的に位置を立て直す
  (quoteの前後文脈→quote単独の順で再検索し、それでも見つからなければ
  「位置が見つからないメモ」として一覧表示し、削除のみ可能にする)
- 歌詞をまとめて貼り付け直すと既存ブロックの部分メモも失われるため、
  その場合は件数を含めて警告を表示する

## Phase 4 でできること

- アーティスト名のオートコンプリート(自前のドロップダウン候補。iOS Safariは
  `<datalist>`の候補表示に対応していないため自前実装にしている)
- アーティスト別画面(登録アーティスト一覧+曲数、タップでそのアーティストの曲一覧)

## Phase 5 でできること

- ジャケット画像の選択(端末から選ぶと、長辺320px・JPEG品質0.8にリサイズ・圧縮してから保存)
- 曲一覧・曲詳細・編集画面でのジャケット画像プレビュー表示(画像なしはこれまでどおり♪のデフォルト表示)
- 画像の削除、差し替え(古い画像はDBから自動的に削除され、残り続けない)

## Phase 6 でできること

- グループの作成・名前変更・削除(削除しても中の曲は削除されない)
- グループへの曲の追加・削除(グループから外しても曲自体は削除されない)
- グループ内の曲の手動並び替え(↑↓)。並び順はグループごとに独立して保存されるため、
  同じ曲が複数グループに入っていても、一方の並び替えが他方に影響しない
- 曲の追加・編集画面での所属グループ選択(複数可)

## Phase 7 でできること

- 設定画面からバックアップの書き出し(「画像を含めて書き出す」「画像を含めずに書き出す」の2種類、単一のJSONファイル)
- 書き出したJSONには `app` / `backupVersion` / `dbSchemaVersion` / `exportedAt` /
  `includesImages` / `counts` などのメタ情報を含む(復元時の形式チェック・件数確認に使用)
- 設定画面からバックアップの読み込み(ファイル選択 → 内容チェック → 件数確認モーダル → 実行)
  - 他アプリのファイルや壊れたJSONは、はっきりしたメッセージで読み込みを拒否する
  - 復元方法は「追加・上書き(既存データは残したまま、同じIDのものだけ上書き)」と
    「完全に置き換え(今のデータを全部消してから復元)」の2つから選べる。
    「完全に置き換え」を選ぶとさらに確認ダイアログが出る
  - 「画像なしバックアップ」を復元した場合、参照先の画像が無いジャケットは
    自動的にデフォルト表示(♪)に修正される
  - 書き込みはそれぞれ1つのIndexedDBトランザクションで行われるため、
    途中で失敗しても中途半端な状態にはならない(自動的に元に戻る)
- 最終書き出し日時を設定画面に表示

## 曲の削除(Phase 7の追加対応)

- 曲の編集画面(既存の曲を開いて「編集」から入った画面)の一番下に
  「この曲を削除」という枠を追加した
- 「この曲を削除する」を押すと確認ダイアログが出て、OKすると
  - 曲そのもの(歌詞・和訳・部分メモ・曲全体メモを含む)
  - 設定していたジャケット画像
  - 所属していたグループの情報(グループ自体・他の曲は消えない)
  がまとめて削除され、曲一覧に戻る
- 元に戻せない操作のため、確認ダイアログを必ず挟むようにしている

## Phase 8 でできること

- 検索画面を本実装。曲名・アーティスト名・アルバム名・歌詞(英語)・和訳(日本語)・
  部分メモ本文・曲全体メモ本文をすべて対象に検索する
- 入力するたびに自動で再検索(少し待ってから実行するため、日本語入力中もちらつきにくい)
- 各ヒットについて「どこにヒットしたか」のラベル(曲名/アーティスト/アルバム/歌詞(英語)/
  和訳/メモ(英語)/メモ(日本語)/曲全体メモ)と、マッチ箇所の前後を含む短い抜粋を表示
- 曲名・アーティスト・アルバムのヒットを、歌詞・メモのヒットより上位に表示
- 結果をタップすると、その曲の詳細画面に移動する

## Phase 9 でできること

- 曲の編集画面で、歌詞ブロックの並び替えをドラッグ操作でできるようにした
  (⠿のつまみを指(またはマウス)でつかんで動かし、離した位置の一番近くに移動する)
- グループ詳細画面で、グループ内の曲の並び替えも同様にドラッグ操作でできるようにした
- どちらも、従来の↑↓ボタンはそのまま残してある
  (ドラッグが苦手な場合や、1つだけ細かく動かしたい場合の代わりの手段として)
- iOS Safariはネイティブのドラッグ&ドロップ(draggable属性)がタッチ操作では
  動かないため、Pointer Events(pointerdown/pointermove/pointerup)を使った
  自前実装にしている

Phase 9でまだ対応していないもの(必要であれば追加で対応):
- ドラッグ中に画面外まで動かした場合の自動スクロール(今は指を離した時点で
  画面内に見えている行の中から一番近いものへ移動する)
- iPhone実機での最終的な見た目調整(実機で気になる点があれば都度教えてください)

## ローカルでの確認方法

`file://` では ES Modules と IndexedDB が正しく動かないため、簡易サーバーを立てて確認します。

```bash
cd lyric-note
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開きます。

## GitHub Pagesでの公開・iPhoneでの確認方法

1. GitHubでアカウントを作成する
2. 新しいリポジトリを作成する(Public、READMEなしでOK。このフォルダの中身をそのままpushするため)
3. このフォルダの中身(index.html, css/, js/, README.md, .gitignore)をリポジトリの最上位にpushする
4. リポジトリの Settings → Pages → Source を「Deploy from a branch」、Branchを「main」/「/(root)」に設定して保存する
5. 数分待つと `https://ユーザー名.github.io/リポジトリ名/` で公開される
6. iPhoneのSafariでそのURLを開く
7. 共有ボタン(□に↑) → 「ホーム画面に追加」を選ぶ
8. ホーム画面のアイコンから起動し、設定画面で「起動方法: ホーム画面から起動 (推奨)」と表示されることを確認する

## 重要: ユーザーデータについて

登録した曲・歌詞・和訳・メモ・画像などのユーザーデータは、すべて端末内のIndexedDBにのみ保存されます。
GitHubリポジトリにはコードだけを置き、データは絶対にpushしないでください
(`.gitignore` でバックアップJSONの誤コミットは防いでいますが、念のため)。

## フォルダ構成

```
index.html
css/
  base.css        変数・リセット
  layout.css      画面全体の骨組み
  components.css  ボタン・カードなどの部品
js/
  main.js         起動処理(DB初期化・ルート登録)
  router.js       ハッシュベースの簡易ルーター
  app-state.js    起動時に読み込むメモリキャッシュ
  data/
    db.js           IndexedDBの接続・スキーマ定義
    repository.js   UIから呼ぶデータアクセス関数(将来Supabase等に差し替え可能)
  domain/
    text-normalize.js  DOM/DBに依存しない純粋関数(アーティスト名正規化・ソート等)
  ui/
    views/       画面単位のコンポーネント(home.js, settings.js など)
    components/  画面をまたいで使う部品(toast.js など)
  utils/
    id.js  dom.js
```
